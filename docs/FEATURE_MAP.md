## Updating a row

Re-run that gate on a Mac. Copy the short SHA, CDHash, and board path into that row's Status. Leave the other rows alone. `RED` adds ` gate=<id> evidence="<grade.json evidence>"`. `UNGRADED` has no CDHash or board; it is for a surface no Mac run has scored.

## How to read a red row

Stage diagnostics (`stages.log`, `trace.py`) grade nothing. Read [qa/v0-diagnostics.md](qa/v0-diagnostics.md) for the first failure, then the gate definition in [qa/v0-grading.md](qa/v0-grading.md).

## v1 Phase 2 — cost metering (planned)

Bar B1: ≤ $0.25 per session-hour, metered over a 60-minute session on a Mac. The plan is [plans/v1-phase2-cost.md](plans/v1-phase2-cost.md). Step A (the meter) is in the tree and ungraded. `PLANNED` means the Mac grade has not been run. A row leaves `PLANNED` only when a Mac run scores its gate: `cost-grade.json` for B1, or recorded console readings for B1-CAL. After that it follows the same Status format as the v0 rows. `swift test` never changes a status. v0 as wired streams two tracks continuously, about $0.40/session-hr, so B1 is expected RED until the Step C lever lands. The B1 profile is speakers with no headphones. `meeting-60m.wav` is synthetic and is a Step B fixture, not in git.
